# `audit/` — 审计环

本目录属于**审计环**，与 `pipeline/`（生产线）是两套规矩相反的东西。放在不同目录，
是为了让这条界线在文件系统层面就看得见。

## 两半的分工

| | 生产线 `pipeline/` | 审计环 `audit/` |
|---|---|---|
| 产出是什么 | **数据**（会成为产品事实源） | **提案**（给人看的建议） |
| 允许猜吗 | 不允许，无证据即 `UNSUPPORTED`（约束四） | 允许 |
| 必须确定性吗 | 必须，同输入同输出 | 不必须 |
| 能用宽网吗 | 不能（约束二） | **就该用** |
| 能用 AI 吗 | 不能 | 能（仅限帮人归纳，产出仍是提案） |
| 能反向修改上游吗 | 不能（约束六） | 环本来就是反向的 |

判断一件事该守哪套规矩，唯一判据是：**它的产出是数据还是提案。**

## 膜的规则

**生产线的任何脚本不得读取审计环的产出。** 地位同 `PROBLEMS.md`（规格 §4.2）——
旧管线的三张补丁清单最初都以"先记录一下"出现，后来被某个脚本读了就变成配置，
再后来变成不可移除的依赖。从第一天堵死这条路径。

**审计环 → 生产线只允许三样东西过去：**

1. 确定性形状（正则，带正反断言）
2. `PROBLEMS.md` 登记项（带可重放的数字）
3. 决策表行（带 `source` / `source_locator`，约束八）

**不允许过去的**：候选行、置信分、AI 判定的 span、任何"看起来像但没验证"的东西。

**生产线 → 审计环允许过去的是信号**：产出文件、宽网差集、field-audit 不变量违反计数、
分类层的拒收模式。信号往回走，数据不往回走。

## 九条约束在两半的分布

- **约束一至六**：生产线的规矩（在产生的那层修、不用清单、不用周边文本判法域、
  无证据不给默认值、不删行、层间单向）。审计环基本不适用。
- **约束七、八**：守在膜上——规定审计环的产出要变成生产线的知识，得满足什么条件。
- **约束九**：**审计环的全部宪法**——不信任任何未经核实的数字。审计环允许猜，
  但任何想穿过膜进规格的数字，必须能重放。

### `gap_audit.py` 用法

```
python audit/gap_audit.py --assert-only        # 只跑断言（19 条），秒级
python audit/gap_audit.py --out data/gap_audit.json
```

输出写进 `data/`（gitignore，机器产物不进 git）。

**它自己的验收指标是"包住率"**：宽网若包不住七形状，"残差"这个概念就不成立。
2026-09-07 实测 98.81%，故**残差是下界，低估约 1.2%**——引用残差数时必须带这个限定。

## 为什么这个目录存在（记一笔）

抽取层的一个真实问题：七形状抓不到的东西，分类层永远看不见——不是"推迟到下一层处理"，
是"永久丢失"。所以需要一个持续发现"像引证但没被抓到"的机制。

但这个机制**不能长在生产线上**：宽网的每一条误报，在决策表填满后都会变成一条
"看起来已验证"的错数据。所以它长在这里——喂形状设计，不喂产出表。

### `table_coverage.py` 用法

```
python audit/table_coverage.py --assert-only          # 只跑断言（23 条形态分类 + 同口径断言）
python audit/table_coverage.py
python audit/table_coverage.py --json data/table_coverage.json
```

**两档设计是刻意的，不是冗余。**

「仅归一命中」独立成档，测的是规格 §8.2 拿 `normalize_code` 作查表键这个设计的**净效应**——
收益与实害各是多少行，混进「精确命中」就永远看不见（PROBLEMS #33 即由此档测出）。

漏网里的「**疑似真法院码**」独立成档，测的是**静默假阴性**。首轮建表时我把漏网整体断言为
「全是厂商码和噪声、落 UNSUPPORTED 是正确行为」并写进了规格与提交信息，实际里面有上百行真代码
（PROBLEMS #34）。这一档存在的意义就是让那句话在机制上说不出口——数字自己会顶出来。
「疑似」是实指：清单里混着 reporter 缩写去点后的同形串，是提案不是判定，入表前须人核。
