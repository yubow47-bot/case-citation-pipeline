# 方法卡：按层的“怎么做、扩展新法院要改什么、哪里踩过坑”

给谁用：往这条 pipeline 加新法院、新引证写法（新正则家族）、新法域的人或模型。
目的：不用重读 150 KB 的规格和 157 KB 的 PROBLEMS，先读对应那一层的卡，再按卡里的指针去查原文。

## 怎么读

| 你要做的事 | 先读 |
|---|---|
| 加一个新法院（跑通整条线） | `00_new_court_playbook.md` |
| 引证抽不到 / 要加新正则家族 | `01_extraction.md` |
| 法域判不出、同形缩写、非案例被当引证、案名切错 | `02_classification.md` |
| 计数、键、案名投票有问题 | `03_merging.md` |

| 门槛、边文件、DD 口径 | `05_selection_and_edges.md` |
| 要往决策表加行 | `06_decision_tables.md` |

| 想知道某个坑以前有没有人踩过 | `08_pitfalls_by_layer.md` |

## 卡片格式（每张卡都是这个顺序）

1. 这一层做什么、输入输出
2. **加新法院时要改什么 / 不用改什么**
3. 怎么验证
4. 已知的坑（带 PROBLEMS 编号和状态）
5. 来源（规格章节、代码位置、PROBLEMS 编号）

## 可靠程度（读之前先看这里）

- 文中写 **【已核实】** 的，我对照代码或实际文件看过（日期见各卡末尾）。
- 写 **【按规格】** 的，来自技术规格 v1.7 或 PROBLEMS 原文，规格自己标着“待复核”的条目没有重新核实。
- 写 **【待核实】** 的，没有对照过代码，不得当作实现依据（约束九）。
- PROBLEMS 编号后面的状态是 2026-10-03 账本里的状态。状态会变，动手前以 `PROBLEMS.md` 原文为准。

## 不可违反的九条约束（任何方案与之冲突，改方案，不改约束）

一、问题在产生它的那一层修，下游不加绕过清单。
二、抽取层不用固定缩写清单，只按结构形状匹配；查表动作放分类层。
三、不读周边文本关键词来判法域。
四、没有证据就是 `UNSUPPORTED`，不给默认值，不用 `inferred` 给猜测发通行证。
五、不删行，只打标记（`rejected_reason`、`kept` 等）。
六、层间单向，每层只跑一次；下游可以否定上游结论，但不改上游文件。
七、决策表的键必须是判决书上印着的事实，不是管线生成的键。
八、决策表每一行必须带 `source` 和 `source_locator`，判定不得写在代码里。
九、没核实过的数字和引文不得当依据。

详见规格 §2。
